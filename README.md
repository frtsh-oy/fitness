# Моя тренировка — Telegram Mini App

Домашняя тренировка с резинками, оформленная как Telegram Mini App.
Статика без сборки: файлы репозитория — ровно то, что отдаёт GitHub Pages.

## Локальный запуск

    python3 -m http.server 8000

Открыть http://localhost:8000/. Вне Telegram приложение работает как обычный
сайт: прогресс уходит в localStorage, а обращения к Telegram API безопасно ни
на что не влияют (SDK на странице подключён всегда, но вне клиента Telegram
он лишь заглушка — см. `telegram.js`).

## Публикация на GitHub Pages

Settings → Pages → Build and deployment → Source: **Deploy from a branch**,
ветка **`main`**, папка **`/` (root)**.

Папка `/docs` в том же выпадающем списке — не она. В `docs/` лежат дизайн,
план и сводка разметки мышц: выбрав её, на публичный адрес уедет план вместо
приложения. Правильный выбор — корень.

Сборки нет: файлы репозитория и есть то, что отдаёт Pages. Файл `.nojekyll`
в корне нужен, чтобы Pages не пропускал их через Jekyll. `test/`, `tools/` и
`src-original/` тоже уедут на Pages — они безвредны, `index.html` их не
подключает.

Проверка после публикации: открыть `https://frtsh-oy.github.io/fitness/`
в анонимном окне (без входа в GitHub) — страница должна открыться и отметки
должны сохраняться.

Pages отдаёт файлы с `Cache-Control: max-age=600`, а имена файлов без версий.
Поэтому в первые десять минут после выкладки у тех, кто открыл приложение
незадолго до неё, возможна смесь старых и новых файлов (новый `app.js` со
старым модулем и пустой раздел). Лечится полным перезапуском Mini App.
`tools/collect-site.mjs` собирает в `dist/` только нужные странице файлы; он
остаётся запасным путём, Pages им не пользуется.

## Тесты

    npm install
    npm test

`npm test` — это `node --test`: отдельный тест-раннер не нужен. DOM в тестах
поднимает jsdom (единственная зависимость, `test/setup.js`); в то, что отдаёт
GitHub Pages, она не попадает — приложение остаётся нулём рантайм-зависимостей.

## Структура

Приложение разделено на четыре раздела с нижней навигацией: «Сегодня»
(нынешняя страница целиком — вступление, блоки, карта тела, недельная
нагрузка, упражнения), «Тренировки» («Мои» и «Готовые»), «Конструктор»
(библиотека упражнений, ручная сборка и подбор по правилам, сохранение своих
тренировок) и «Отдых» (таймер — шторка, поднимающаяся по нажатию, а не полоса
во всю ширину). Подробнее о разделах — в
`docs/superpowers/specs/2026-09-19-sections-shell-design.md`, о конструкторе —
в `docs/superpowers/specs/2026-10-19-workout-builder-design.md`.

| Файл | Ответственность |
|---|---|
| `app.js` | связывание: берёт выбранную тренировку (готовую или свою), рисует «Сегодня», прогресс, таймер, обработчики событий; соединяет «Тренировки» и «Конструктор» со своими тренировками |
| `sections.js` | нижняя навигация: показ и скрытие разделов, их запоминание между запусками |
| `workouts-view.js` | раздел «Тренировки» — «Мои» (свои тренировки человека, «Изменить», «Удалить», пометка «только на этом устройстве») и «Готовые» (реестр); карточка делает тренировку текущей |
| `builder-view.js` | раздел «Конструктор»: вход, ручная сборка, подбор по уровню и зонам упора с экраном результата, замена упражнения, сохранение |
| `library-view.js` | экран библиотеки упражнений: поиск по названию, мышцам, движению и инвентарю; фильтр по зоне на виду, а сложность, движение, «только без инвентаря» и «Что есть дома» — под «Ещё фильтры»; «Как выполнять» и видео, «Добавить»; про конструктор ничего не знает |
| `gear.js` | словарь инвентаря (пять видов и «без инвентаря»), подписи и правило «подходит ли упражнение»; единственный источник для схемы, импорта таблицы и экранов |
| `gear-profile.js` | «Что есть дома»: выбор человека в `localStorage` (ключ `gear-owned`), по умолчанию длинная резинка и мини-петля; недоступное хранилище — выбор живёт в памяти |
| `gear-picker.js` | переключатели «Что есть дома»: один блок на генератор и библиотеку |
| `my-workouts.js` | свои тренировки: запись `u_<id>` в CloudStorage и копия на устройстве, не больше 50, досылка в облако при запуске |
| `kv.js` | ключ-значение поверх CloudStorage и localStorage, без исключений наружу; на нём стоят `storage.js` и `my-workouts.js` |
| `own.js` | `hasOwn`: проверка «собственное свойство» вместо `Object.hasOwn`, которого нет в iOS до 15.4 и Chrome до 93; вызовы стоят на пути запуска |
| `builder/rules.js` | правила подбора: уровни, зоны упора, основные группы, границы и числа (только данные) |
| `builder/arrange.js` | порядок силовых упражнений и разбиение на пары |
| `builder/texts.js` | тексты своей тренировки: шапка, блоки, подсказки, склонение чисел |
| `builder/compact.js` | сжатая запись своей тренировки (списки ключей упражнений) и её развёртка в полную тренировку, которую проверяет та же схема |
| `builder/coverage.js` | какие основные группы остались без нагрузки или ниже границы уровня |
| `builder/generator.js` | подбор тренировки по уровню и зонам упора либо отказ с причиной: чего не хватает библиотеке и какой инвентарь закрыл бы пробел |
| `builder/replace.js` | кандидаты на замену упражнения и сама замена |
| `exercises/library.csv` | снимок таблицы упражнений, как при последнем импорте |
| `exercises/library.js` | библиотека, которую читает приложение; строится импортом, руками не правится |
| `exercises/index.js` | упражнение по ключу, подписи типа и сложности |
| `exercises/README.md` | как вести таблицу упражнений и обновлять библиотеку |
| `render.js` | построение DOM по объекту тренировки |
| `workouts/legs-mwf.js` | данные тренировки: тексты, круги, порядок; упражнения берутся из библиотеки по ключу |
| `workouts/schema.js` | валидатор схемы и подсчёт отметок |
| `workouts/index.js` | реестр тренировок |
| `muscles.js` | словарь групп мышц и свёртка в регионы картинки |
| `volume.js` | расчёт подходов по группам и регионам мышц |
| `bodymap.js` | карта тела: слой над библиотекой body-highlighter |
| `figure.js` | дорисовка фигуры поверх схемы библиотеки: стопы, кисти, голова со спины |
| `vendor/` | сборка body-highlighter 3.0.2 (MIT) и её лицензия |
| `weekly.js` | расчёт недельного объёма подходов по группам мышц, в двух системах счёта |
| `load-bands.js` | границы недельного объёма и вердикт по ним, с источником у каждой |
| `weekly-rows.js` | общая сборка строк недельного объёма (расчёт + вердикт + подпись + сортировка) для экрана и отчёта |
| `weekly-view.js` | экран недельного объёма: раскрывающийся список с обоими числами и вердиктом |
| `storage.js` | прогресс: CloudStorage внутри Telegram, localStorage снаружи |
| `telegram.js` | слой Telegram с деградацией вне мессенджера |
| `timer.js` | таймер отдыха |
| `player.js` | видео с фолбэком на внешнее открытие |
| `tools/muscle-report.js` | генератор `docs/muscle-map.md` — сводка разметки мышц для вычитки человеком и раздел недельного объёма; см. ниже |
| `tools/import-exercises.mjs` | импорт таблицы упражнений (CSV) в `exercises/library.csv` и `exercises/library.js`; см. ниже |
| `tools/library-report.js` | чего не хватает библиотеке каждому уровню и каждой зоне упора, по трём наборам инвентаря: весь, только резинки, без инвентаря |
| `tools/library-sync.gs` | скрипт таблицы (Google Apps Script): меню «Приложение → Выложить библиотеку»; в таблицу копируется руками |
| `.github/workflows/library-sync.yml` | импорт, сводка и тесты для кнопки таблицы; всё зелёное — коммит в `main` |
| `test/` | тесты (`node:test`); `test/setup.js` поднимает jsdom |
| `src-original/` | архив исходного сайта, только для сверки |

`tools/` — инструмент разработки, а не часть приложения: `index.html` его не
подключает и в браузере он не исполняется. На Pages он всё-таки уезжает вместе
с остальным деревом (публикуется корень ветки целиком), но ничего там не делает.

## Библиотека упражнений и таблица

Все упражнения приложения описаны в одной таблице Google Sheets, которую ведёт
владелец: одна строка — одно упражнение. Из таблицы берётся всё, что видно на
карточке: название, техника, видео, инвентарь, сложность, нагрузка по мышцам.
Готовая тренировка и свои тренировки упражнения не хранят, а ссылаются на них по
ключу, поэтому правка в таблице доходит до всех тренировок сразу. Сама таблица в
репозиторий не входит: приложение читает только `exercises/library.js`.

Главный путь — кнопка в самой таблице: меню «Приложение → Выложить библиотеку»
(скрипт `tools/library-sync.gs`, ставится в таблицу один раз, как — в
`exercises/README.md`). Скрипт кладёт лист коммитом в ветку `library-sync`, а
действие `.github/workflows/library-sync.yml` делает шаги 2–4 ниже и, если всё
зелёное, коммитит в `main`, то есть в прод. Импорт отказал — `main` не тронут, а
ошибки скрипт показывает прямо в таблице.

Тот же путь руками (команды — из папки проекта; колонки, правила и разбор
отказов — в `exercises/README.md`):

1. Поправить таблицу, затем Файл → Скачать → Формат CSV (.csv).
2. `node tools/import-exercises.mjs "<путь к скачанному файлу>"` — перезапишет
   `exercises/library.csv` (снимок таблицы: в истории git видно, что поменялось)
   и `exercises/library.js`. Вместо файла можно дать ссылку на опубликованный
   лист, но тогда таблица становится читаемой для всех, у кого есть ссылка;
   сейчас её не публикуют.
3. `node tools/muscle-report.js` — обновит `docs/muscle-map.md`, в нём разметку
   новых упражнений вычитывает человек. До `npm test`: тест сверяет сводку с
   генератором и после любой правки разметки краснеет, пока её не пересобрали.
4. `npm test`.
5. `node tools/library-report.js` — покажет, чего не хватает каждому уровню и
   каждой зоне упора по трём наборам инвентаря (весь, только резинки, без
   инвентаря): по нему видно, какие упражнения добавлять следующими и кому
   генератор пока откажет.
6. Pull request в `main`.

Импорт принимает таблицу целиком или не пишет ничего: все найденные ошибки
печатаются разом, с номером строки и названием колонки. Отдельный отказ — «ключ
был в библиотеке и пропал из таблицы»: сохранённые тренировки ссылаются на
упражнения по ключу. Если упражнение убрано намеренно, импорт запускают с
`--allow-removed=ключ1,ключ2` (только на названные ключи). Подробности — раздел
«Если импорт отказал» в `exercises/README.md`. Ключ упражнения не меняется
никогда: из него строится отметка «сделано» и на него ссылаются сохранённые
тренировки.

Сложность, многосуставность и разметка мышц — инженерное суждение по описанию
упражнения, а не заключение специалиста; проверяет их только человек, по
`docs/muscle-map.md`.

## Конструктор

Раздел «Конструктор» бесплатный и даёт тренировку на всё тело двумя путями.
Правила, уровни, зоны упора и откуда взяты числа — в
`docs/superpowers/specs/2026-10-19-workout-builder-design.md`; здесь только то,
что нужно знать, работая с кодом.

- **Собрать самому.** Человек листает библиотеку (поиск без учёта регистра и
  разницы «е» и «ё» по названию, подписи мышц, целевым группам, движению и
  инвентарю, каждое слово запроса; фильтр по зоне; под «Ещё фильтры» —
  сложность, движение, «только без инвентаря» и «Что есть дома»; «Как
  выполнять» и видео в карточке) и добавляет силовые упражнения, лишнее убирает. Разминка,
  разогрев и завершение подставляются сами, их можно заменить. Пока не все
  основные группы получают нагрузку, на экране сборки висит предупреждение; оно
  пересчитывается при каждом добавлении и удалении, а сохранить можно и с ним.
- **Сгенерировать.** Человек выбирает уровень и до двух зон упора, упражнения
  подбираются по правилам из библиотеки, а на экране результата любое можно
  заменить на похожее. Одинаковый выбор и зерно дают одинаковую тренировку,
  «Другой вариант» меняет зерно.

**Что есть дома.** Человек отмечает инвентарь, который у него есть: длинная
резинка, мини-петля, резинка с ручками, гантели, гиря (по умолчанию отмечены
первые два). Генератор, библиотека упражнений, скелет ручной сборки и замена
предлагают только подходящее: упражнение подходит, если каждый его вид
инвентаря отмечен или это «без инвентаря». Если уровню или зоне не хватает
упражнений из-за инвентаря, отказ называет, какой инвентарь нужен. Сохранённые
и готовые тренировки выбором не фильтруются. Выбор лежит только на устройстве
(`localStorage`, ключ `gear-owned`) и между устройствами не переезжает; словарь
инвентаря — `gear.js`, спека —
`docs/superpowers/specs/2026-10-21-gear-profile-design.md`.

В обоих случаях на сохранении нужны название и хотя бы один день недели; один
день — предупреждение, а не запрет. Правила подбора лежат в `builder/rules.js`,
а не в экранах.

**Где хранится.** Своя тренировка — одна запись `u_<id>` в CloudStorage
Telegram, а вне Telegram — в `localStorage`, тем же слоем, что отметки. В записи
только ключи упражнений (`builder/compact.js`), а полная тренировка собирается
при открытии из библиотеки и проходит ту же проверку схемы, что и готовая.
Поэтому карта тела, недельная нагрузка, отметки и таймер работают на ней без
изменений, а правка библиотеки доходит и до неё. Упражнение, которого уже нет в
библиотеке, пропускается, и экран об этом говорит. Сервера нет, на сервере
тренировки не лежат.

**Не больше 50 своих тренировок**: CloudStorage держит до 1024 записей на
человека вместе с отметками. Пятьдесят первую сохранить нельзя, экран говорит
почему. Запись идёт сначала на устройство, потом в облако. Если облако не
ответило, тренировка сохранена на устройстве, в «Мои» у неё пометка «только на
этом устройстве», а при следующем запуске приложение досылает её в облако
(`my-workouts.js`). Если не вышло записать и на устройство, человек видит
отказ, и тренировка остаётся на экране сборки.

**В «Тренировки → Мои»** карточка делает свою тренировку текущей и открывает
«Сегодня»; «Изменить» открывает её в конструкторе (подобранную — на результате
с заменой, собранную руками — на сборке), «Удалить» спрашивает подтверждение.
Если удалить текущую, текущей станет готовая по умолчанию. Недельная нагрузка в
«Сегодня» считает только текущую тренировку, повторённую в её дни.

**Когда генератор отказывает.** Хватает ли упражнений, зависит от библиотеки и
от инвентаря человека: на часть основных групп или на второе упражнение для
упора их может не быть, и тогда уровень или зона недоступны. Экран говорит,
чего не хватает и каким инвентарём это закрывается, а
`node tools/library-report.js` показывает пробелы по трём наборам инвентаря:
весь, только резинки (выбор по умолчанию) и без инвентаря. Ручная сборка
доступна всегда.

Оплаты в приложении нет, и проверки подписки нет: `access.js`, который её
изображал, убран. Когда появится сервер, вопрос решается заново в
`docs/superpowers/specs/2026-09-19-subscription-server-design.md`.

## Разметка мышц и её вычитка

Поле `load` у каждого упражнения — какие группы мышц оно нагружает, целевые и
вспомогательные — инженерное суждение по описанию упражнения, а не заключение
тренера. Живёт оно в библиотеке (колонки мышц таблицы упражнений, дальше
`exercises/library.js`), а тренировки из `workouts/*.js` берут упражнения оттуда.
Ошибка в нём ничего не ломает и нигде не падает: `workouts/schema.js` проверяет
только форму (группа существует в словаре `muscles.js`, значение 1 или 0.5), а
не то, верна ли она по смыслу. Такую ошибку может найти только человек,
читающий текст глазами.

    node tools/muscle-report.js

перегенерирует `docs/muscle-map.md`: по каждой тренировке — таблицу
«упражнение → мышцы» и сводку подходов по группам, отдельно для силовых,
разминочных и заминочных упражнений (это разная по характеру нагрузка, и
складывать её в одну сумму было бы нечестно). В таблице рядом с размеченными
группами стоит `item.muscles` — подпись, которую человек видит на карточке
упражнения: два описания одного факта видно рядом, и расхождение между ними
заметно глазом. Файл сгенерирован — правится не он, а таблица упражнений (см. «Библиотека
упражнений и таблица»), после чего импорт и генератор запускаются заново.

## Карта тела

Секция «Что работает в этой тренировке» показывает на схеме, какие группы
мышц нагружены, и по клику на мышце открывает список её упражнений. Объём
области — это доля нагрузки упражнения, умноженная на число кругов блока и
просуммированная по упражнениям: то же правило, по которому считает
`docs/muscle-map.md` (там суммы по группам мышц и раздельно по типам, здесь —
по областям схемы и за типы выбранного режима). По клику показывается оно, как
есть, поэтому бывает дробным: «Трапеции — 2,5 подх.». Цвет берётся от него же,
округлённого до целого: шкала библиотеки различает только целые подходы.
Округление живёт в `bodymap.js` и нужно одному цвету — число, которое видит
человек, не округляется никогда.

Переключатель над схемой выбирает, что считать. «Силовые» — режим по
умолчанию, в цвет идут только силовые упражнения, а что происходит в
разминке и заминке, сказано строкой под схемой. «Вся нагрузка» — разминка,
силовые и заминка одним числом; это ответ на вопрос «что тренировка вообще
задевает», и в нём становится видно, например, пресс, который работает в
основном в разминке. Переключатель влияет на всё, что показывает карта:
цвет, число подходов в подборе и список упражнений в нём. Выбранный режим
запоминается на устройстве, как и то, раскрыта ли секция.

Палитра — шесть оттенков, и откалибрована она под силовой режим, где максимум
на область ровно шесть подходов. В режиме всей нагрузки суммы больше
(квадрицепсы 12,5, ягодичные 9,5, пресс 6,5), и последний оттенок достаётся всем,
у кого округлённое число подходов дошло до шести, — то есть уже с 5,5. Так в
один цвет сливаются пять областей: квадрицепсы, ягодичные, пресс, верх спины
(5,5) и передняя дельта (5,5). Шкалу мы не растягиваем под максимум режима
намеренно — иначе цвет перестал бы значить одно и то же в обоих режимах, а
потом и в разных тренировках. Подпись под схемой про верх шкалы молчит:
объяснение через округление владелец программы просил убрать с экрана, и место
подробностям — здесь. А именно: оттенок берётся по округлённому числу
подходов, поэтому самый тёмный означает шесть и больше, то есть уже с 5,5.
Точное число всегда в одном клике.

Выбранная кликом область заливается брендовым синим — не обводится: на экране
телефона обводка почти не видна. Сделано это седьмым цветом палитры, который
уходит в библиотеку вместе с шестью оттенками объёма: какой полигон какой мышце
принадлежит, из разметки не видно (`data-*` библиотека не ставит), поэтому
красить приходится через её же правило «цвет по числу подходов». Отсюда две
особенности. Первая: число подходов у невыбранных областей ограничивается
шестёркой, иначе квадрицепсы с их 12,5 дотянулись бы до седьмого цвета и
выглядели бы выбранными; на самом цвете это не сказывается — шесть подходов и
так последний оттенок шкалы. Вторая: пока область выбрана, её цвет нагрузки не
виден, потому что полигон залит синим целиком. Смена режима выбор снимает —
вместе с подбором, который к прежнему режиму уже не относится.

Сама библиотека, которая рисует схему (`vendor/`), лежит в репозитории, а
не загружается по ссылке из интернета (CDN): на плохой связи внешняя
ссылка могла бы просто не сработать, и схема бы не открылась.

Фигура дорисована: у библиотеки размечены только мышцы, поэтому её человечек
без стоп и кистей, а голова со спины у него почти круглая — 19,1 × 20,0 против
19,2 × 25,3 спереди (в единицах её схемы). Своя часть — стопы, кисти и эллипс
головы со спины — лежит в `figure.js` и рисуется тем же серым, каким библиотека
заливает незатронутую мышцу. Стопы и кисти ложатся поверх её полигонов, эллипс
головы — под них: он заходит на задние трапеции, и поверх закрывал бы 2,2% их
площади цвета нагрузки серым клином у шеи. Область отрисовки поднята с
библиотечной `0 0 100 200` до `-8 0 116 232`: в свой бокс библиотека не влезала
и сама — заднюю голень она рисует до y=220, то есть двадцать единиц её просто
не попадали в картинку. Библиотека заменяет содержимое схемы целиком при каждой
отрисовке, поэтому дорисованное возвращается после каждой — это закрыто
тестами в `test/bodymap.test.js`.

Файл библиотеки при этом не правится ни одним символом, и координаты
`figure.js` на это опираются: они сняты с её полигонов. Чтобы правка файла не
прошла молча, его содержимое привязано контрольной суммой SHA-256 в
`test/vendor.test.js` — любое изменение роняет тест. Сверки с пакетом на npm
там нет и быть не может: сети в тестах нет, а шапка файла документирует два
намеренных отличия от опубликованной сборки (вписан полный текст MIT, убрана
строка `sourceMappingURL`). Обновление версии библиотеки — это отдельная
работа: правим файл, перепроверяем координаты `figure.js` по новой геометрии,
ставим новую сумму.

Стоит знать о двух ограничениях. Первое — библиотека делит тело на свои
области, а они крупнее наших групп мышц. Заметнее всего это на дельтах: у
нас их три пучка — передний, средний и задний, — а библиотека даёт под
дельту только две области, переднюю и заднюю. Средний пучок пришлось
отнести к передней: отдельного места под боковую дельту у библиотеки просто
нет. Поэтому клик по передней области возвращает упражнения переднего и
среднего пучков сразу, а по задней — только заднего.

Такие общие области — три из семнадцати: квадрицепсы (с ними сгибатели
бедра), верх спины (с широчайшими) и передняя дельта (со средней). В подборе
по такой области подпись под заголовком прямо говорит, почему в нём названо
несколько мышц; по остальным четырнадцати её нет — объяснять там нечего.
Постоянного абзаца об этом под схемой тоже нет: он объяснял затруднение
раньше, чем человек с ним столкнётся.

Второе — по силуэту нельзя перемещаться клавишей Tab и выбирать мышцу с
клавиатуры. Открыть и закрыть саму секцию с клавиатуры можно, и переключить
режим тоже — это обычные кнопки. А вот нажать на конкретную мышцу на картинке
получится только мышью или пальцем на экране: так устроена сторонняя
библиотека, которая рисует силуэт. Существенно здесь то, что клавиатурой
недоступен способ, а не сама информация: какие мышцы работают в упражнении,
написано на его карточке в приложении, а вся разметка целиком расписана в
`docs/muscle-map.md`. Всё, что показывает карта, доступно и без неё — карта
лишь собирает это в картинку. Добавить клавиатурный доступ к каждой из 66
областей на обеих схемах мы могли бы, но не стали: это добавило бы десятки
лишних остановок при переходе по странице клавишей Tab и только усложнило
бы навигацию с клавиатуры, а не облегчило её — тем более что все упражнения
и так можно найти прокруткой страницы или кнопками блоков тренировки вверху
страницы.

## Сколько получает каждая мышца за неделю

Под картой тела есть ещё один раскрывающийся список — «Сколько получает
каждая мышца за неделю». Он отвечает на вопрос, не однобокая ли программа:
сколько подходов набирает каждая мышца за неделю, если выбранную тренировку
делать в её дни (а не только за одну тренировку), и много это или мало по
сравнению с тем, что показали исследования силовых тренировок. Считается
только силовая работа — разминка и заминка сюда не попадают, это другая по
характеру нагрузка.

У каждой мышцы в списке два числа, и это не ошибка. Второе — то же самое,
что считает карта тела: если в упражнении мышца не главная, а помогает, ей
засчитывается половина подхода. Первое число устроено иначе: помогающая роль
не считается вовсе, зато упражнение «на одну ногу» или «на одну руку» даёт
подход на каждую сторону отдельно, а не один на весь круг, как в приложении.
Так первое число и получается сопоставимым с тем, как считали исследователи,
на которых опирается программа, — поэтому итоговый вывод сделан именно по
нему, а второе число оставлено рядом просто для сравнения с картой.

Сам вывод — одна из пяти подписей, дословно тех же слов, что и в приложении:

- «не тренируется целенаправленно» — ноль подходов в неделю: на эту мышцу в
  программе нет ни одного упражнения, где она главная;
- «работает, но не оптимально» — 1–4 подхода: нижняя из изученных категорий,
  рост есть, но не лучший из возможных;
- «поддержание и слабый рост» — 5–9 подходов: примерно столько нужно, чтобы
  удержать набранный результат; какой-то рост при этом ещё идёт, но медленный;
- «рабочий объём» — 10–20 подходов: с десяти начинается верхняя из изученных
  категорий. Больше подходов в среднем давало больше роста, но разница именно
  между тремя этими категориями получилась не настолько уверенной, чтобы
  считать её доказанной. Нижнюю границу, десять, дало исследование, а верхнюю,
  двадцать, провели мы сами;
- «выше нашей границы» — больше 20 подходов: двадцать — это наша линия, а не
  край изученного. Верхняя категория в исследовании открытая, «десять и
  больше», и общего потолка исследования не называют — поэтому калькулятор не
  называет это и «перегрузкой».

Есть два случая, когда калькулятору не стоит доверять больше, чем он может
дать.

Первый — он умеет считать количество, а не качество. Подход, сделанный в
полную силу, и подход, сделанный вполсилы, для него выглядят совершенно
одинаково: сколько было реального усилия, из данных программы не видно.
Число подходов — это не гарантия результата, а только его часть.

Второй — про упражнения «на одну сторону». Для отметки в приложении
достаточно одного раза, если сделаны обе стороны, а вот в первом числе
калькулятора такое упражнение считается дважды — по разу на каждую сторону.
Это наше собственное решение, а не то, что прямо написано в исследованиях:
единого мнения, как правильно считать односторонние упражнения при сравнении
с общими нормами, в проверенных источниках нет.

Из пяти границ вывода из исследований взяты не все: ноль — это просто «нет ни
одного упражнения, где мышца главная», а двадцать провели мы сами. Где чьё
число, чем каждое обосновано и ссылки на исследования — в файле
`docs/superpowers/specs/2026-09-18-weekly-load-calculator-design.md`.

## Известное ограничение: отметки не сливаются между устройствами

Прогресс за день — один набор отметок (`storage.js`). Сохранение отправляет в
CloudStorage (а вне Telegram — в localStorage) весь набор целиком, а не
разницу с предыдущей записью. Слияния версий с разных устройств нет: чей набор
уйдёт в хранилище последним, тот и останется.

Это осознанное решение, а не недосмотр — спецификация слияния между
устройствами не обещала. Но если открыть одну и ту же тренировку одновременно
на телефоне и на планшете и отмечать на обоих, при следующем сохранении набор
одного из устройств будет полностью заменён набором другого.

localStorage при этом работает как сквозной кэш: запись идёт в него всегда и
синхронно, ещё до обращения к облаку, и только потом уходит в CloudStorage.
Поэтому день не теряется ни при обрыве связи, ни если приложение закрыли
раньше, чем облако ответило. Локальная копия не перебивает облако сама по
себе — только пока последняя запись не подтверждена (признак `:pending` рядом
с ключом); как только облако подтвердило, главным снова становится оно.

Одна оговорка про этот признак. Если облако запись приняло, но ответ не дошёл
(связь оборвалась в этот момент), признак остаётся висеть, и до следующей
подтверждённой записи локальная копия считается главной. Сброс, сделанный за
это время с другого устройства, не отобразится — и следующая обычная отметка
перезапишет его. Окно узкое и требует совпадения двух событий, но знать о нём
стоит: если сбросили отметки на планшете, а на телефоне они остались, сделайте
сброс и там.

Важная деталь: перезапись случается только по действию человека, а не молча
при открытии приложения. При загрузке `app.js` добавляет то, что пришло из
хранилища, к тому, что уже отмечено на экране (объединяет, а не заменяет), и
ничего не пишет обратно, пока не отметить хотя бы один чекбокс. Поэтому просто
открыть тренировку на втором устройстве, ничего на нём не трогая, — безопасно;
теряет отметки именно параллельная работа на двух устройствах сразу.

### Ключ отметок и чистка старых

До этой версии ключ отметок содержал двоеточие (`w:<id>:<день>`), а
CloudStorage принимает ключи только из латиницы, цифр, `_` и `-`. Telegram
отвечал на каждую запись отказом, `storage.js` его ловил, и отметки фактически
жили только на устройстве: до другого устройства они не доходили вовсе. Это
вывод из документации Telegram, а не живая проверка, ни до правки, ни после.
Проверить можно так: отметить упражнение на одном устройстве и открыть
приложение на другом.

Теперь ключ выглядит как `m_<id>_<день>`, и тест на каждый формат ключа следит,
чтобы облако получало только разрешённые символы. Старые отметки не
переносятся: они живут один день, поэтому в день обновления сегодняшние
отметки начинаются заново.

Отметки старше вчерашнего дня удаляются при запуске, и с устройства, и из
облака: в CloudStorage всего 1024 записи на человека, а каждый день тренировки
иначе занимал бы одну из них навсегда. Вчерашние не трогаются: у другого
устройства в другом часовом поясе «сегодня» может оказаться нашим «вчера».

## Добавить тренировку

1. Создать `workouts/<id>.js` по образцу `legs-mwf.js`. Упражнения в нём не
   описываются, а берутся из библиотеки по ключу (`item('rdl')`): нужного
   упражнения нет — сначала строка в таблице и импорт.
2. Добавить строку в `WORKOUTS` в `workouts/index.js`.
3. Обновить сводку для вычитки: `node tools/muscle-report.js`. До тестов: они
   сверяют сводку с генератором, и новая тренировка без пересборки их краснит.
4. Прогнать `npm test` — валидатор проверит форму разметки.

Как только в реестре появится вторая запись, в «Готовых» появится вторая
карточка. Нажатие на карточку делает тренировку текущей и открывает «Сегодня»
без перезагрузки; выбор запоминается на устройстве (`current-workout` в
`localStorage`) и восстанавливается при запуске. Ссылка (`?w=<id>` в браузере,
`startapp=<id>` в Telegram, раздел «Открыть конкретную тренировку» ниже)
важнее запомненного, но запомненное не перезаписывает.

### Поля, на которых легко ошибиться

Источник истины по форме — `workouts/schema.js`; `npm test` прогоняет его по
всем тренировкам реестра. Несколько полей, где ошибка не очевидна:

| Поле | Что важно |
|---|---|
| `key` у упражнения | Обязателен, уникален внутри блока. Из него строится идентификатор отметки `блок-key-круг`, поэтому смена key стирает сегодняшние отметки этого упражнения, а по позиции в массиве его строить нельзя — вставка упражнения перенесла бы отметки на соседей |
| `days` | Дни недели по ISO-8601: `[1, 3, 5]` — это ПН/СР/ПТ. Обе строки расписания на странице выводятся отсюда, отдельного текста расписания в данных нет |
| `equipment` | Строка инвентаря для шапки — не путать с `gear` у упражнения, там перечисление из `gear.js`: `band_long`, `loop_short`, `band_handles`, `dumbbells`, `kettlebell`, `none` |
| `load` | Обязателен у каждого упражнения и непуст у всех, кроме помеченных `pattern: recovery`: это ещё и «какие упражнения есть на эту мышцу» для карты тела, поэтому растяжки размечены наравне с силовыми. Разминку и заминку от объёма отделяет `kind`, а не пустая разметка. Пустой `load` разрешён только при `pattern: recovery` (`NO_LOAD_PATTERN` в `workouts/schema.js`) — это утверждение «упражнение не тренирует ничего», а не забытая разметка, и сейчас такое упражнение одно: «Спокойное дыхание» |
| `v`, элементы `links` | `[id, старт, подпись]`, id ролика YouTube ровно 11 символов. Не та форма — плеер молча не включится |

## Открыть конкретную тренировку

- В браузере: `?w=<id>` — например, `http://localhost:8000/?w=legs-mwf`.
- В Telegram, через бота [@fitdomabot](https://t.me/fitdomabot):
  `t.me/fitdomabot/<app>?startapp=<id>`, где `<app>` — короткое имя мини-аппа
  (задаётся один раз через `/newapp` в BotFather). Если указаны оба источника,
  `startapp` побеждает `?w=`.
- Без `id` из обоих источников (или с неизвестным) открывается запомненная
  тренировка, а если запомненной нет — тренировка по умолчанию
  (`DEFAULT_WORKOUT_ID` в `workouts/index.js`).
