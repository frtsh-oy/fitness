# Моя тренировка — Telegram Mini App

Домашняя тренировка с резинками, оформленная как Telegram Mini App.
Статика без сборки: файлы репозитория — ровно то, что отдаёт GitHub Pages.

## Локальный запуск

    python3 -m http.server 8000

Открыть http://localhost:8000/. Вне Telegram приложение работает как обычный
сайт: прогресс уходит в localStorage, а обращения к Telegram API безопасно ни
на что не влияют (SDK на странице подключён всегда, но вне клиента Telegram
он лишь заглушка — см. `telegram.js`).

## Тесты

    npm install
    npm test

`npm test` — это `node --test`: отдельный тест-раннер не нужен. DOM в тестах
поднимает jsdom (единственная зависимость, `test/setup.js`); в то, что отдаёт
GitHub Pages, она не попадает — приложение остаётся нулём рантайм-зависимостей.

## Структура

| Файл | Ответственность |
|---|---|
| `app.js` | связывание: роутинг, прогресс, таймер, подписки |
| `render.js` | построение DOM по объекту тренировки |
| `workouts/legs-mwf.js` | данные тренировки |
| `workouts/schema.js` | валидатор схемы и подсчёт отметок |
| `workouts/index.js` | реестр тренировок |
| `muscles.js` | словарь групп мышц и свёртка в регионы картинки |
| `storage.js` | прогресс: CloudStorage внутри Telegram, localStorage снаружи |
| `telegram.js` | слой Telegram с деградацией вне мессенджера |
| `timer.js` | таймер отдыха |
| `player.js` | видео с фолбэком на внешнее открытие |
| `tools/muscle-report.js` | генератор `docs/muscle-map.md` — сводка разметки мышц для вычитки человеком; см. ниже |
| `test/` | тесты (`node:test`); `test/setup.js` поднимает jsdom |
| `src-original/` | архив исходного сайта, только для сверки |

`tools/` — инструмент разработки, а не часть приложения: `index.html` его не
подключает, и в продакшен (GitHub Pages) он не попадает.

## Разметка мышц и её вычитка

Поле `load` у каждого упражнения в `workouts/*.js` — какие группы мышц оно
нагружает, целевые и вспомогательные — инженерное суждение по описанию
упражнения, а не заключение тренера. Ошибка в нём ничего не ломает и нигде не
падает: `workouts/schema.js` проверяет только форму (группа существует в
словаре `muscles.js`, значение 1 или 0.5), а не то, верна ли она по смыслу.
Такую ошибку может найти только человек, читающий текст глазами.

    node tools/muscle-report.js

перегенерирует `docs/muscle-map.md`: по каждой тренировке — таблицу
«упражнение → мышцы» и сводку подходов по группам, отдельно для силовых,
разминочных и заминочных упражнений (это разная по характеру нагрузка, и
складывать её в одну сумму было бы нечестно). Файл сгенерирован — правится не
он, а `workouts/*.js`, после чего генератор запускается заново.

## Известное ограничение: отметки не сливаются между устройствами

Прогресс за день — один набор отметок (`storage.js`). Сохранение отправляет в
CloudStorage (а вне Telegram — в localStorage) весь набор целиком, а не
разницу с предыдущей записью. Слияния версий с разных устройств нет: чей набор
уйдёт в хранилище последним, тот и останется.

Это осознанное решение, а не недосмотр — спецификация слияния между
устройствами не обещала. Но если открыть одну и ту же тренировку одновременно
на телефоне и на планшете и отмечать на обоих, при следующем сохранении набор
одного из устройств будет полностью заменён набором другого.

Важная деталь: перезапись случается только по действию человека, а не молча
при открытии приложения. При загрузке `app.js` добавляет то, что пришло из
хранилища, к тому, что уже отмечено на экране (объединяет, а не заменяет), и
ничего не пишет обратно, пока не отметить хотя бы один чекбокс. Поэтому просто
открыть тренировку на втором устройстве, ничего на нём не трогая, — безопасно;
теряет отметки именно параллельная работа на двух устройствах сразу.

## Добавить тренировку

1. Создать `workouts/<id>.js` по образцу `legs-mwf.js`.
2. Добавить строку в `WORKOUTS` в `workouts/index.js`.
3. Прогнать `npm test` — валидатор проверит форму разметки.
4. Обновить сводку для вычитки: `node tools/muscle-report.js`.

## Открыть конкретную тренировку

- В браузере: `?w=<id>` — например, `http://localhost:8000/?w=legs-mwf`.
- В Telegram, через бота [@fitdomabot](https://t.me/fitdomabot):
  `t.me/fitdomabot/<app>?startapp=<id>`, где `<app>` — короткое имя мини-аппа
  (задаётся один раз через `/newapp` в BotFather). Если указаны оба источника,
  `startapp` побеждает `?w=`.
- Без `id` из обоих источников открывается тренировка по умолчанию
  (`DEFAULT_WORKOUT_ID` в `workouts/index.js`).
