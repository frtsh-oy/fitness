# Карта тела (S2) — дизайн

Дата: 2026-09-17
Статус: утверждён
Предыдущая итерация: `2026-09-14-telegram-mini-app-design.md`, раздел S1

## Задача

Показать на схеме тела, какие группы мышц работают в тренировке, и дать
перейти от мышцы к её упражнениям. Область — одна существующая тренировка
`legs-mwf`; экрана выбора тренировок в этой итерации нет.

Это подсистема S2 из дорожной карты предыдущей спеки. Фундамент для неё —
разметка `load` у всех 19 упражнений, сделанная в S1.

## Решения

| Решение | Выбор |
|---|---|
| Назначение | подсветка объёма плюс отклик на клик |
| Что означает подсветка | рабочие подходы на группу, только силовые |
| Разминка и заминка | показываются отдельной строкой, не на карте |
| Расположение | свёрнутая секция вверху, раскрывается по клику |
| Библиотека | `body-highlighter` 3.0.2, MIT, сборка лежит в репозитории |

Отклонено: загрузка библиотеки с CDN — появился бы третий внешний адрес и
отказ на плохой сети, ровно тот класс отказа, который в предыдущей итерации
стоил шести раундов правок в хранилище. Отклонено: рисовать свою анатомию —
отдельная большая работа не про этот проект.

## Проверенные свойства библиотеки

Установлены чтением исходников пакета, а не по описанию:

- `createBodyHighlighter({ container, data, type, onClick, bodyColor, highlightedColors, style, svgStyle })`
  возвращает `{ element, update, destroy }`.
- `data: [{ name, muscles: string[], frequency?: number }]`.
- Интенсивность считается как `acc[muscle].frequency += exercise.frequency || 1`,
  то есть переданная `frequency` суммируется по мышце.
- Цвет выбирается как `highlightedColors[Math.min(len - 1, frequency - 1)]`.
  Значит объём выражается напрямую: подходы становятся индексом в палитре.
- `onClick` получает `{ muscle, data: { exercises, frequency } }` — список
  названий упражнений на эту мышцу приходит от библиотеки.
- `type` принимает `anterior` и `posterior`. Оба вида обязательны: ягодичные,
  задняя поверхность бедра и спина на переднем виде не видны.
- Сборка ESM — 18.2 КБ, внешних импортов внутри нет.

## Правки таксономии

Словарь регионов в `muscles.js` расходится со словарём библиотеки. Это
отложенная находка из предыдущей итерации («причесать до того, как строки
станут идентификаторами в DOM») — закрывается здесь.

| Группа | Было | Станет |
|---|---|---|
| `adductors` | `adductors` | `adductor` |
| `glutes_med` | `gluteal` | `abductors` |
| `delts_front` | `deltoids` | `front-deltoids` |
| `delts_rear` | `deltoids` | `back-deltoids` |
| `delts_side` | `deltoids` | `front-deltoids` |

`glutes_med` переезжает в `abductors` не ради совместимости, а потому что это
анатомически верно: средняя и малая ягодичные отводят бедро. Побочно они
получают отдельный регион на картинке вместо слияния с большой ягодичной.

У библиотеки нет региона боковой дельты. `delts_side` отдаётся
`front-deltoids`: на переднем виде шапка плеча и есть видимая масса дельты.
Это осознанное приближение, оно подписывается комментарием в коде.

## Архитектура

```
vendor/body-highlighter.esm.js    чужой код, не изменяется
vendor/body-highlighter.LICENSE   MIT, сохранение обязательно
volume.js                         тренировка -> подходы по группам и регионам
bodymap.js                        слой над библиотекой
muscles.js                        правки region
```

`volume.js` отделён от `bodymap.js` намеренно: расчёт объёма — будущая основа
оценки нагрузки S4, и он обязан быть тестируемым без DOM и без библиотеки.
Он не знает ни про библиотеку, ни про разметку страницы.

`bodymap.js` не знает про конкретную тренировку: получает объект тренировки и
контейнеры, строит записи, создаёт два вида, обрабатывает клик.

### Интерфейсы

`volume.js`:
- `setsByGroup(workout, kind) -> Map<groupId, number>` — подходы по нашим
  группам для упражнений заданного типа; сумма `load × rounds`.
- `setsByRegion(workout, kind) -> Map<region, number>` — то же, свёрнутое в
  регионы картинки.
- `exerciseEntries(workout, kind) -> [{ name, muscles: [region], frequency }]` —
  по одной записи на пару «упражнение × группа», готовые для библиотеки.

`bodymap.js`:
- `createBodyMap({ workout, anteriorHost, posteriorHost, onPick }) -> { destroy }`
  где `onPick({ muscle, exercises })` вызывается при клике по мышце.

## Поток данных

```
workout
  -> exerciseEntries(workout, 'strength')
     Румынская тяга, 2 круга, load {hamstrings:1, glutes:1, lower_back:0.5}
       { name:'Румынская тяга', muscles:['hamstring'],  frequency: 2 }
       { name:'Румынская тяга', muscles:['gluteal'],    frequency: 2 }
       { name:'Румынская тяга', muscles:['lower-back'], frequency: 1 }
  -> библиотека суммирует по мышце и красит по индексу в палитре
```

Подходы дробные (доля 0.5 на круг даёт 1.5), а индекс палитры целый. Округление
до ближайшего целого, минимум 1 для любой задействованной группы: группа с
половиной подхода обязана быть подсвечена, а не выглядеть незадействованной.

Палитра — шесть оттенков лайма от бледного к насыщенному, производные от
фирменного `#ceef69`. Шесть, потому что максимум в текущей тренировке —
шесть подходов на ягодичные.

## Взаимодействие

Свёрнутая строка «Что работает в этой тренировке» стоит после навигации по
блокам и до счётчика отметок. По клику раскрывается:

- два вида рядом, передний и задний; на узком экране — друг под другом;
- под ними строка о том, что добавляет разминка, со списком групп, которые
  силовыми не грузятся вовсе;
- подпись о том, что серые мышцы в этой тренировке не задействованы.

Клик по мышце показывает её название, число подходов и список упражнений;
клик по упражнению прокручивает к нему на странице.

Состояние «раскрыта или свёрнута» запоминается напрямую в `localStorage`
отдельным ключом, а не через адаптер прогресса: у того интерфейс — множество
отметок за день, и флаг интерфейса в него не помещается по смыслу. Это
per-device удобство, а не данные тренировки: терять его при смене устройства
не жалко, синхронизация через облако ему не нужна. Обращение к `localStorage`
оборачивается так же, как в адаптере: в приватном режиме оно бросает.

## Проверка

- `volume.js` — чистыми тестами без DOM: подходы по группам совпадают с тем,
  что печатает `docs/muscle-map.md`; типы упражнений считаются раздельно;
  дробные доли округляются как задумано.
- `bodymap.js` — на jsdom с подделкой библиотеки: правильные записи, правильные
  регионы, клик доходит до обработчика.
- Живая проверка в браузере: раскрытие, оба вида, клик по мышце, переход к
  упражнению, мобильный вьюпорт 375×812, отсутствие ошибок в консоли.
- Проверка на опубликованном адресе после выкладки.

## Риски

1. **Карта рисует регионы, а не наши группы.** После правок `glutes` и
   `glutes_med` расходятся, но три пучка дельт всё равно сжимаются в два. Клик
   по дельте вернёт упражнения всех пучков. Это неизбежно при чужой картинке;
   подписывается в интерфейсе.
2. **Икроножные и предплечья не грузятся ни одним упражнением** и останутся
   серыми. Это правда, а не дефект, но глаз может решить, что карта не
   работает — отсюда подпись про серые мышцы.
3. **Вес страницы растёт на 18 КБ.** Библиотека грузится вместе с
   приложением, а не по требованию. Если это окажется заметно на медленной
   сети, следующим шагом — загружать её при первом раскрытии карты.

## Вне объёма

Экран выбора из нескольких тренировок, составление своих тренировок, случайная
тренировка, оценка недельной нагрузки со светофором. Карта обязана им не
мешать, но реализовывать их сейчас не нужно.
