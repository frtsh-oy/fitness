# Telegram Mini App «Моя тренировка» — дизайн

Дата: 2026-09-14
Статус: утверждён

## Задача

Сделать Telegram Mini App, открывающий тренировку с резинками, и привязать его к боту.

Источник контента — существующий сайт `band-workout-mwf.adwirk-gmbh-7623.chatgpt.site`.
Использовать его напрямую нельзя: анонимный запрос возвращает `401 Unauthorized`,
сайт закрыт логином ChatGPT, и в Telegram WebView пользователь упрётся в экран входа.
Контент переносится на собственный хостинг.

## Решения

| Решение | Выбор |
|---|---|
| Объём | Одна тренировка (`legs-mwf`), архитектура с заделом на несколько |
| Хостинг | GitHub Pages, аккаунт `yanad-adw`, работа через веб-интерфейс в профиле Chrome «Ya» |
| Привязка к боту | Только BotFather: `/newapp` + кнопка меню. Серверного процесса нет |
| Внешний вид | Фирменная палитра сайта (тёмно-синий + лаймовый), не тема Telegram |
| Подход | Порт существующей статики + вынос данных тренировки в отдельный модуль |

Отклонено: переписывание на фреймворк (16 КБ работающего ванильного JS не нуждается
в сборке); бот с обработчиком `/start` и напоминаниями ПН/СР/ПТ — требует сервера,
хранилища подписчиков и планировщика, отложено до следующей итерации.

## Исходный материал

Сайт — чистая статика из пяти файлов, без бэкенда:
`index.html` (30 КБ), `app.js` (16 КБ, данные + рендер), `player.js` (3 КБ),
`style.css`, `player.css`.

Видео не хостится — это эмбеды `youtube-nocookie.com`, собираемые из id ролика.
Прогресс хранится в `localStorage`.

Содержание: 8 блоков, 19 упражнений, 37 отметок (1x2 + 3x4 + 2x2x5 + 1x3).

## Архитектура

```
tg-workout/
├─ index.html        оболочка: шапка, контейнер, нижняя панель таймера
├─ app.js            рендерер: принимает объект тренировки → строит DOM
├─ workouts/
│  ├─ index.js       реестр: id → модуль, дефолтная тренировка
│  └─ legs-mwf.js    данные: 8 блоков, 19 упражнений
├─ telegram.js       слой Telegram: init, тема, safe area, BackButton, haptics
├─ storage.js        адаптер прогресса: CloudStorage ↔ localStorage
├─ player.js         YouTube: ленивый iframe + фолбэк на openLink
├─ style.css
└─ player.css
```

Границы ответственности:

- `app.js` не знает ни одной конкретной тренировки — только схему.
- `workouts/*.js` — чистые данные, без логики и без DOM.
- `telegram.js` и `storage.js` не знают про тренировки вообще.
- `player.js` зависит только от разметки упражнения, не от данных.

Каждый модуль проверяем отдельно: рендерер — на фикстуре, хранилище — на подменённом
бэкенде, слой Telegram — на заглушке `window.Telegram`.

## Контракт файла тренировки

```js
export default {
  id: 'legs-mwf',
  kicker: 'ДОМА · С РЕЗИНКАМИ',
  title: 'Всё тело. Акцент на ноги.',
  lead: 'Ягодицы и внутренняя поверхность бедра — в фокусе…',
  schedule: 'ПН · СР · ПТ',
  stats: [{ v: '65–80', l: 'минут с отдыхом' }, { v: '3 + 2', l: '…' }],
  gear: 'Нужно: коврик, короткие и длинные резинки…',
  pairRules: 'Первое упражнение → 30–45 с отдыха → …',
  blocks: [{
    id: 'start', n: '01', title: 'Стартовая разминка',
    sub: 'Плавно, без длительных остановок',
    rounds: 1,
    note: '10–20 с между упражнениями…',   // необязательно
    items: [{
      name: 'Подкручивание таза лёжа',
      muscles: 'Таз и поясница',
      reps: '8–10 раз',
      text: 'Ляг на спину, согни колени…',
      detail: '…',                          // необязательно, раскрывается
      extra: '…',                           // необязательно, прогрессия
      v: ['VZ3f0pSTObM', 20, '0:20'],       // необязательно: [youtubeId, стартСек, подпись]
      links: [],                            // необязательно, доп. ролики
      key: '…'                              // необязательно
    }]
  }],
  progression: ['…'],
  caution: '…'
}
```

Правило расширения: новая тренировка — это новый файл в `workouts/` плюс одна строка
в `workouts/index.js`. Рендерер при этом не меняется. Если для новой тренировки
потребуется изменить рендерер, значит схема неполна — расширяем схему, а не рендерер.

## Слой Telegram

Инициализация в `telegram.js`, вызывается один раз до первого рендера:

- `ready()` и `expand()` — открывать сразу на всю высоту.
- `disableVerticalSwipes()` — обязательно. Страница длинная; без этого свайп вниз
  закрывает приложение вместо прокрутки.
- `setHeaderColor()` и `setBackgroundColor()` в фирменный тёмно-синий — чтобы шапка
  Telegram не отличалась от шапки приложения.
- Safe area: нижняя панель таймера получает
  `padding-bottom: calc(<высота панели> + var(--tg-safe-area-inset-bottom, 0px))`,
  иначе на iPhone она уходит под системную полосу.
- `BackButton` — показывается при скролле ниже первого блока, по нажатию возврат наверх;
  на самом верху скрыт.
- `HapticFeedback.impactOccurred('light')` на отметке упражнения,
  `notificationOccurred('success')` при закрытии блока целиком.

Роутинг тренировки, по убыванию приоритета:
`initDataUnsafe.start_param` → query-параметр `?w=` → дефолт из реестра.
Неизвестный id — молча дефолт, без экрана ошибки.

Деградация: при отсутствии `window.Telegram?.WebApp` приложение работает как обычный
сайт. Ни один вызов Telegram API не должен ронять страницу в обычном браузере.

## Прогресс

Единый интерфейс: `get()`, `set(key, value)`, `reset()`.

Бэкенд выбирается при старте: `CloudStorage`, если доступен (Bot API 6.9+),
иначе `localStorage`. Ключ включает id тренировки и дату — поведение
«отметки сбрасываются на следующий день» сохраняется как на исходном сайте.

`CloudStorage` асинхронный, поэтому рендер его не ждёт: разметка строится сразу,
отметки применяются по готовности. Пустого экрана на время загрузки быть не должно.

Лимит `CloudStorage` — 1024 ключа на пользователя. Пишем один ключ на тренировку,
так что запас избыточный.

## Деплой

Push с этой машины не настроен: нет `gh` CLI и credential helper, а вводить токены
в рамках этой работы нельзя. Поэтому выкладка через веб-интерфейс GitHub
в профиле Chrome «Ya»:

1. Создать репозиторий `tg-workout` (публичный — GitHub Pages на бесплатном плане).
2. Загрузить файлы проекта.
3. Settings → Pages → Deploy from branch, `main`, папка `/` (root).
4. Проверить, что `https://yanad-adw.github.io/tg-workout/` открывается анонимно.

Каждое необратимое действие (создание репозитория, публикация) подтверждается
пользователем отдельно.

## Привязка к боту

Выполняет пользователь в Telegram; ассистент готовит текст инструкции.

1. `/newbot` — бот ещё не создан.
2. `/newapp` → выбрать бота → название, описание, иконка 640×360,
   URL = адрес GitHub Pages, короткое имя. Результат — `t.me/<бот>/<app>`.
3. `/setmenubutton` → тот же URL, подпись «Тренировка».

Токен бота не требуется ни для сборки, ни для деплоя, и ассистенту не передаётся.

## Проверка

На ассистенте:

- Локальный `python3 -m http.server`: рендер всех 8 блоков и 19 упражнений,
  счётчик 37 отметок, сохранение и сброс, таймер, раскрытие видео.
- Вьюпорт 375×812: нижняя панель, safe area, отсутствие горизонтальной прокрутки.
- Заглушка `window.Telegram.WebApp`: вызовы Telegram API идут, при её отсутствии
  страница работает без ошибок в консоли.
- Контент сверяется с исходным сайтом: ни одно упражнение, описание или ролик
  не должны потеряться при переносе.

На пользователе (эмулятор не заменяет):

- Реальный запуск в Telegram на телефоне: воспроизведение видео, поведение свайпов,
  синхронизация прогресса между устройствами, вид шапки.

## Риски

1. **YouTube в WebView.** Эмбеды обычно играют, но на части устройств блокируются.
   Закладывается фолбэк: при ошибке загрузки iframe — `WebApp.openLink()`
   на обычную ссылку ролика, откроется в приложении YouTube.
2. **Старые клиенты Telegram.** `CloudStorage` требует Bot API 6.9+,
   safe area — 8.0+. Обе фичи проверяются перед использованием,
   при отсутствии — тихая деградация, а не ошибка.
3. **Иконка для `/newapp`.** Нужна картинка 640×360; если своей нет — генерируется.

## S1. Таксономия мышц и разметка упражнений

Входит в эту итерацию. Это фундамент для карты тела, конструктора и оценки
нагрузки — без него любая из этих подсистем потребует переразметки всех упражнений.

### Словарь групп

Гранулярность выбрана та, на которой реально считают объём тренировки, —
группа мышц, а не отдельный пучок.

```
Ноги и таз : glutes, glutes_med, quads, hamstrings, adductors, calves
Корпус     : abs, obliques, lower_back, hip_flexors
Верх       : lats, upper_back, traps, chest,
             delts_front, delts_side, delts_rear, biceps, triceps, forearms
```

Словарь — единственный источник истины, живёт в `muscles.js` вместе с русскими
подписями. Строки вроде «Внутренняя поверхность бедра» остаются в данных как
человекочитаемая подпись, но для логики используется только идентификатор.

### Разметка упражнения

К схеме упражнения добавляются поля:

```js
{
  // …существующие поля…
  load: { hamstrings: 1, glutes: 1, lower_back: 0.5 },
  pattern: 'hinge',        // hinge | squat | lunge | push | pull | core | mobility | stretch
  gear: ['band_long'],     // band_long | loop_short | none
  unilateral: false,
  kind: 'strength'         // warmup | strength | cooldown
}
```

`load` — доля рабочего подхода, которую упражнение даёт группе мышц:
`1` для целевой группы, `0.5` для вспомогательной. Разминочные и заминочные
движения (`kind` = `warmup` / `cooldown`) в объём не засчитываются: у них `load`
либо пустой, либо не учитывается при подсчёте.

`pattern`, `gear`, `unilateral` нужны конструктору и генератору случайной
тренировки: без них «рандом» выдаёт несбалансированный набор, а фильтр
по инвентарю невозможен.

### Слой соответствия библиотеке

Наши идентификаторы не должны совпадать с идентификаторами какой-либо библиотеки.
Соответствие «наша группа → регион на картинке» живёт отдельным объектом
в `muscles.js`. Несколько наших групп могут указывать на один регион
(`glutes` и `glutes_med` → ягодичная область; три пучка дельт → одна дельта).
Замена библиотеки карты тела — правка одного файла.

### Достоверность разметки

Разметка составляется по описаниям упражнений и является инженерным суждением,
а не заключением тренера. После заполнения её нужно вычитать — особенно доли
`0.5` у вспомогательных групп. Ошибка здесь тихо искажает всю будущую оценку
нагрузки, поэтому разметка выносится в отдельный, легко проверяемый файл
и сопровождается сводной таблицей «упражнение → группы» для вычитки.

## Дальнейшие итерации

Реализуются отдельно, каждая со своим циклом «дизайн → план → реализация».
Текущая архитектура обязана им не мешать, но реализовывать их сейчас не нужно.

| | Подсистема | Зависит от |
|---|---|---|
| S2 | Интерактивная карта тела: клик по мышце → упражнения на неё | S1 |
| S3 | Конструктор: выбор с карты, случайная тренировка, свои тренировки | S1, S2 |
| S4 | Оценка нагрузки: «мало / норма / перебор» по группам | S1, S3 |

Библиотека карты тела выбрана предварительно: `body-highlighter` 3.0.2,
MIT, без зависимостей, не привязана к фреймворку. Решение окончательно
фиксируется в дизайне S2.

### Ограничения модели нагрузки (S4)

Фиксируются заранее, потому что влияют на разметку в S1:

- Объём считается в рабочих подходах на группу мышц в неделю.
  Ходовой ориентир для роста — порядка 10–20 подходов; меньше — скорее
  поддержание, больше — риск не восстановиться.
- Ориентиры получены преимущественно на свободных весах. Для резинок подход —
  условная единица: сопротивление зависит от растяжения и от выбранной петли.
- Оценка подаётся как светофор-ориентир, а не медицинское заключение,
  и сопровождается той же оговоркой, что уже есть в блоке про боль.

## Вне объёма всех итераций (пока)

Обработчик `/start`, напоминания по расписанию ПН/СР/ПТ, синхронизация прогресса
через собственный бэкенд, история тренировок и статистика по неделям.
