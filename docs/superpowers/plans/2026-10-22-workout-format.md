# Формат своей тренировки — план реализации

> **Для исполнителей:** задачи выполняются по одной, по порядку. Шаги отмечены `- [ ]`.

**Цель:** блоки разминки, разогрева и завершения своей тренировки включаются и
выключаются, силовая часть строится парами, кругом или подходами.

**Устройство:**
- Формат хранится полем `format` в сжатой записи.
- Выключенный блок — пустой список упражнений.
- `expandWorkout` раскладывает силовые по формату в обычные блоки схемы, поэтому «Сегодня» рисует их без новой логики. Новое у блока только необязательное поле `unit: 'sets'`, оно меняет подписи отметок.
- Переключатели — отдельный модуль `format-picker.js`, встроенный в сборку и в результат генератора.

**Стек:** статические ES-модули без сборки, `node --test` + jsdom.

**Спека:** `docs/superpowers/specs/2026-10-22-workout-format-design.md`

## Общие ограничения

- Без сборки и без рантайм-зависимостей. Комментарии и тексты по-русски, в стиле окружающего кода (комментарий объясняет «почему»).
- Тексты ниже дословные: на них опираются тесты.
- Тесты на фикстурах (`test/fixtures/test-library.js`) и своих маленьких записях, не на составе `exercises/library.js`.
- `exercises/library.*` и `docs/muscle-map.md` руками не правятся; `node tools/muscle-report.js` не даёт diff.
- Доступность как у соседних переключателей (`gear-picker.js`): кнопки `type=button`, `aria-pressed`, группы `role="group"` с подписью.
- Экран 375×812, ничего не переносится уродливо.
- Перед коммитом `npm test` весь зелёный (на старте 917). Около 150 строк jsdom «scrollTo» — шум.

## Где проверять в первую очередь

1. Запись, сохранённая до этой правки (без `format`), открывается, правится и сохраняется как «Пары».
2. Недельная нагрузка по группам одинакова во всех трёх форматах.
3. Включение блока, для которого нет подходящих по «Что есть дома» упражнений: переключатель остаётся выключенным, причина названа.
4. «Другой вариант» сохраняет формат и выключенные блоки.
5. В «Сегодня» у формата «Подходы» подписи «Подход N» и «N подхода», у остальных «Круг N» и склонённое «N круга / кругов».

- [ ] **Шаг 4. Развёртка (`expandWorkout`).** Обозначения: `r = roundsOf(compact)`; порядок силовых `order = arrangeStrength(found.strength).flat()`.
  - `pairs`: как сейчас.
  - `loop`: один блок:
    - `id: 'loop'`, `nav: 'Силовые'`, `title: 'Силовой круг'`;

    - `sub` — группы упражнения, как у пары: `capitalize(groupsPhrase(pairGroups([e])))`;
    - `rounds: r`, `unit: 'sets'`; у первого блока `preamble: SETS_PREAMBLE`.
  - Нет силовых — нет и силовых блоков.

  - Шапка `stats[1]` (`hasCircuit` — в тренировке есть блок разогрева):

    | формат | `v` | `l` с разогревом | `l` без разогрева |

  Тесты на фикстурах (4 силовых + скелет), для каждого формата:
  - `validateWorkout` без проблем;
  - id, `nav`, `title`, `sub`, `rounds`, `unit`, `preamble` только у первого силового блока;
  - номера `n` идут подряд;
  - порядок ключей силовой части одинаков во всех форматах;
  - недельная нагрузка по группам (функция из `volume.js`, которой пользуется `coverage`) одинакова во всех трёх;

  Тесты:

  - клик по блоку зовёт `onBlock` с нужным слотом и перечитывает `state`;
  - причина показывается и снимается;
  - клик по формату меняет пояснение;
  - два блока с разными `idPrefix` не дают одинаковых id.

- [ ] **Шаг 2. Встраивание в `builder-view.js`.**
  - `startManual` кладёт в черновик `format: DEFAULT_FORMAT`.
  - Общая функция создаёт переключатели для текущего экрана: `state` из `draft`, а блок включён, если `draft[slot].length > 0`.
    - `onBlock(slot)`:
      - включён → `draft = { ...draft, [slot]: [] }`;

    - `onFormat(id)` → `draft = { ...draft, format: id }`, затем `refresh()`.
  - Сборка: переключатели после «Добавить упражнение» и его причины, перед списком блоков. Результат: после «Другой вариант» и отказа, перед блоками. `idPrefix` — `build-format` и `result-format`.

  - `edit` открывает запись с её форматом. У старой записи без `format` выбрано «Пары»: запись уже прошла `parseCompact`, но тест на это нужен.
